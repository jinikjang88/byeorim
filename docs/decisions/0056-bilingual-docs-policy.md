# ADR 0056. 한/영 듀얼 문서 정책

- 상태: 채택
- 날짜: 2026-05-08
- 결정자: DevSmith

## 맥락

벼림은 한국에서 시작된 글로벌 오픈소스 표준을 지향한다(CLAUDE.md 섹션 1). 1순위 사용자(카페 사장님, 학원 원장님)가 한국어 화자이고, 메인테이너의 모국어도 한국어라 모든 문서가 한국어로 시작됐다. 동시에 글로벌 표준이 되려면 영어 사용자가 첫 페이지에서 막히면 안 된다.

오픈소스 공개 1단계 작업(2026-05-08, 워크로그 다섯/여섯/일곱 번째 세션)에서 README, CONTRIBUTING, CODE_OF_CONDUCT, SECURITY 4종에 영문판이 함께 박혔다. LICENSE는 MIT 표준 영문이라 그대로다. 영문판은 한국어판을 단어 단위로 옮긴 결이 아니라, "같은 약속을 영어 사용자에게 자연스러운 결로 다시 쓴" 결로 만들어졌다.

이제 두 판본이 존재하니 정책이 필요하다. 어느 쪽이 정본인가, 한쪽이 바뀔 때 다른 쪽은 어떻게 따라가는가, 새 문서가 늘어날 때 영문판은 언제 만드는가. 이 ADR이 그 결을 박는다.

이 ADR이 답하는 질문은 셋이다.

1. 한/영이 어긋날 때 어느 쪽이 정본인가
2. 한쪽이 바뀔 때 sync 책임은 누구에게 있는가
3. 영문판이 필요한 문서의 범위는 어디까지인가

## 검토한 옵션

### 결정 1. 정본 (Source of Truth)

#### 옵션 A. 한국어 정본, 영문은 번역 (이번 채택)

장점:
- 1순위 사용자가 한국어 화자라 한국어판 정확성이 우선
- 메인테이너 모국어가 한국어라 결을 살리는 글이 한국어에서 먼저 나온다
- 기존 4종 영문판이 이미 "Korean original is canonical" 한 줄을 박은 결과 정합
- 도메인 용어(벼림, 7단계 메타포)가 한국어에서 시작된 결을 보존

단점:
- 영문 화자가 본 영문판이 살짝 뒤쳐지는 결이 가끔 발생
- 영문 기여자가 영문판만 고쳐 PR을 보내면 한국어판도 함께 갱신해야 한다는 결을 안내해야 함

#### 옵션 B. 영어 정본, 한국어는 번역

- 장점: 글로벌 사용자에게 즉시 신뢰
- 단점: 메인테이너 결과 1순위 사용자 결이 모두 어긋남. 영문판이 한국어판보다 먼저 나오는 결이 부자연스러움

#### 옵션 C. 두 판본 동등

- 장점: 어느 쪽도 뒤쳐지지 않음
- 단점: 어긋났을 때 어느 쪽이 맞는지 판정할 결이 없어 운영이 흐려짐. 1인 메인테이너 결과 안 맞음

### 결정 2. Sync 책임

#### 옵션 A. 같은 PR에서 함께 갱신 (이번 채택)

- 한국어판 변경 PR은 영문판 갱신을 같은 PR에 포함한다. 영문판 변경 PR도 같은 결
- 메인테이너 또는 외부 기여자가 한쪽만 고치면 리뷰에서 다른 쪽도 함께 고치도록 안내
- 장점: 두 판본 시점이 항상 같음. "Korean original is canonical" 한 줄이 의미를 유지
- 단점: 외부 영문 기여자에게 한국어 갱신을 요구하는 결이 진입 장벽. 다만 메인테이너가 같은 PR에서 한국어를 메우는 결로 보완

#### 옵션 B. 한국어가 먼저, 영문은 후속 PR로

- 장점: 외부 영문 기여자 진입이 쉬움
- 단점: 영문판이 영원히 뒤쳐질 위험. "Korean original is canonical"의 의미가 약해짐

#### 옵션 C. 자동화

- 장점: 사람 부담이 0에 가까움
- 단점: 결을 살리는 번역은 자동화하기 어렵다. 기계 번역은 글쓰기 원칙(섹션 10) 정신을 못 따라감. 1인 메인테이너 결로는 도구 운영 비용도 큼. 차후 검토할 자리

### 결정 3. 영문판이 필요한 문서 범위

#### 옵션 A. 외부 진입점만 (이번 채택)

영문판이 반드시 필요한 결.
- README.md (저장소 첫 페이지)
- CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md (외부 기여자 진입점)
- LICENSE (MIT 표준 영문이라 한국어판 없음)

영문판이 권장되지만 필수가 아닌 결.
- docs/MANIFESTO.md — 외부 관심 신호가 보이면 박는 결
- 주요 ADR (예: 0001, 0006, 0007 같은 핵심 결정) — 차후

영문판이 필요 없는 결.
- 워크로그(docs/worklog/) — 메인테이너 작업 기록이라 한국어로 충분
- 일반 ADR — 결정 기록이라 한국어가 정본
- packages/ 안의 도메인 주석 — 한국어 환영(섹션 8)

장점: 1단계로 외부 진입이 막히지 않으면서 운영 부담을 키우지 않음. 글로벌 관심 신호가 보일 때 점진 확장

단점: 영문 사용자가 ADR이나 워크로그를 보려 하면 한국어 벽에 막힘. 다만 README.en.md가 그 결을 미리 안내(괄호 Korean 표기)

#### 옵션 B. 모든 docs/ 영문판

- 장점: 영문 사용자가 어디서든 막히지 않음
- 단점: ADR 50개 이상, 워크로그 수십 개를 모두 영문화하는 결은 1인 메인테이너 결로 비현실적. 글쓰기 결을 잃을 위험도 큼

#### 옵션 C. 영문판 없음

- 장점: 운영 부담 0
- 단점: 글로벌 표준 지향과 어긋남. 이미 1단계에서 영문 4종이 박혀 있어 무효 결

## 결정

### 결정 1: 한국어 정본 (옵션 A)

한국어판이 정본이고 영문판은 같은 약속을 영어 사용자에게 옮긴 결이다. 두 판본이 어긋나면 한국어판이 맞다. 모든 영문 문서 상단에 "Korean original is canonical" 한 줄을 박는다(이미 1단계 4종에 박혀 있음).

### 결정 2: 같은 PR에서 함께 갱신 (옵션 A)

한국어판이 바뀌는 PR은 영문판 갱신을 같은 PR에 포함한다. 외부 영문 기여자가 영문판만 고쳐 PR을 보내면 메인테이너가 리뷰에서 한국어 갱신을 함께 박거나 외부 기여자에게 안내한다. 머지 게이트는 다음과 같다.

- 한/영 듀얼 문서가 있는 항목을 수정하는 PR은 두 판본을 함께 갱신해야 머지 가능
- 외부 영문 기여자가 한국어를 못 짤 결이면 PR 본문에 "한국어 갱신 필요" 표시. 메인테이너가 결을 채워 넣음

### 결정 3: 외부 진입점만 영문판 의무 (옵션 A)

영문판 의무 문서: README.md, CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md (LICENSE는 MIT 표준 영문)

영문판 권장 문서(차후): docs/MANIFESTO.md, 핵심 ADR (0001, 0006, 0007). 외부 관심 신호가 보일 때 박는다.

영문판 미박 문서: 워크로그, 일반 ADR, 도메인 주석. 한국어가 정본 결로 그대로 둔다.

## 결과

### 긍정적

- 두 판본 정본 결이 분명. 어긋났을 때 판정할 단일 진실 소스
- 1인 메인테이너 결로 운영 부담을 키우지 않음
- 외부 영문 사용자가 첫 페이지에서 막히지 않으면서 메인테이너의 한국어 결을 보존
- 영문판 범위가 외부 진입점에 한정되어 글로벌 확장 시점을 점진 결로 잡을 수 있음

### 부정적 / 트레이드오프

- 영문 사용자가 ADR이나 워크로그로 가면 한국어 벽에 막힘. README.en.md가 미리 안내하지만 완벽한 진입은 아님
- 한국어판 변경 PR마다 영문판 갱신 부담. 1인 메인테이너 결에 부담이 누적될 수 있음
- 외부 영문 기여자가 영문판만 고쳐 보내면 메인테이너가 한국어를 메워야 함. 진입 결이 살짝 늘어남

### 미래 묶임

- 차후 docs/MANIFESTO.md 영문판이 필요해지면 별도 ADR 없이 이 정책의 "권장" 결로 처리
- 핵심 ADR(0001, 0006, 0007) 영문판이 필요해지면 같은 결
- 자동 번역 결을 도입하려면 ADR로 별도 결정. 글쓰기 원칙(섹션 10)과 결이 맞물려야 함
- 1.0 출시 시점에 영문판 범위가 더 넓어질 수 있음. 그때 이 ADR을 갱신 또는 대체
