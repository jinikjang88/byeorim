# ADR 0055. 프로젝트 이름을 벼름에서 벼림으로 변경

- 상태: 채택
- 날짜: 2026-05-08
- 결정자: DevSmith

## 맥락

지금까지 프로젝트의 한국어 이름은 "벼름"이었고 영문 식별자는 `beoreum`이었다. ADR 0001(why-beoreum)에서 결정된 결이고, 그 뒤로 .beoreum/ 디렉토리, `beoreum` CLI 바이너리, `beoreum` npm 패키지명, 모든 문서가 이 이름을 따랐다.

오픈소스 공개를 앞두고 사용자가 이름을 다시 들여다봤다. "벼름"과 "벼림" 둘 다 "벼리다"(쇠를 달구어 두드려 날카롭게 만들다)에서 온 명사형이다. 다만 두 결이 약간 다르다. 사용자는 "벼림"이 더 적합하다고 판단했다. 이번 ADR이 그 결정을 기록한다.

이번 ADR이 답하는 질문은 둘이다. 첫째, 왜 벼림인가. 둘째, 어떻게 마이그레이션하는가.

## 검토한 옵션

### 결정 1. 새 이름

#### 옵션 A. 벼림 / byeorim (이번 출시)

장점:
- 어감: "벼름"보다 "벼림"이 한국어 화자에게 더 자연스럽고 부드럽다. "벼리다 → 벼림"은 동사의 명사형으로도 결이 더 곧다
- 발음: 영문 표기 byeorim이 영어권 화자에게도 발음이 더 분명하다. beoreum은 모음 연속(eo+e+u)이 길어 발음이 흐려진다
- 검색성: byeorim은 영문 검색 시 다른 단어와 겹치지 않는다. beoreum은 일부 외국어 단어와 시각적으로 비슷하다
- 의미: 벼림은 "다듬어 만들어내는 행위"의 결이 강하다. 코드 이전에 아이디어를 다듬는다는 Beoreum의 사명과 더 또렷하게 맞물린다
- 사용자(DevSmith)의 개인 스토리 연장: 사용자의 다른 작업과 이름의 결을 잇기 위해 벼림이 더 알맞다

#### 옵션 B. 벼름 / beoreum 유지

- 장점: 마이그레이션 비용이 0
- 단점: 위 다섯 가지가 모두 미해결

### 결정 2. 마이그레이션 범위

#### 옵션 A. 모든 흔적 제거 (이번 출시)

- 본문 텍스트: `beoreum` → `byeorim`, `BEOREUM` → `BYEORIM`, `Beoreum` → `Byeorim`, `벼름` → `벼림` 일괄 치환
- 디렉토리: `.beoreum/` → `.byeorim/`
- 바이너리: `bin/beoreum.js` → `bin/byeorim.js`, npm bin `beoreum` → `byeorim`
- 패키지명: `beoreum` → `byeorim`
- IDE 설정: `.idea/beoreum.iml` → `.idea/byeorim.iml`
- 이름이 박힌 ADR 파일명: `0001-why-beoreum.md` → `0001-why-byeorim.md`, `0007-beoreum-directory-layout.md` → `0007-byeorim-directory-layout.md`, `0047-beoreum-run-command.md` → `0047-byeorim-run-command.md`
- 워크로그 본문도 일괄 치환

장점: 한 결로 통일. 새 기여자가 두 이름이 섞인 저장소를 보고 혼란하지 않는다

단점: 역사 기록(워크로그, ADR 본문)을 바꾸는 결은 평소 결과 다르다. 이번에는 이름이 워낙 깊이 박혀 있어 본문에서만 갱신하고 파일 자체는 새로 쓰지 않는 결로 정합을 맞춘다

#### 옵션 B. 새 이름은 신규부터, 기존은 유지

- 단점: 두 이름이 영원히 섞여 새 기여자가 매번 헷갈린다. 프로토타입 단계라 외부 사용자도 거의 없으니 깨끗이 바꾸는 비용보다 섞여 있는 비용이 크다

## 결정

### 결정 1: 벼림 / byeorim 채택 (옵션 A)

이유는 어감, 발음, 검색성, 의미, 사용자 개인 스토리 연장 다섯 가지다. 위 옵션 A에 풀어 적었다.

### 결정 2: 모든 흔적 제거 (옵션 A)

본문, 파일명, 디렉토리명, 패키지명, 바이너리명을 모두 갱신한다. 이름이 박힌 ADR 3개(0001, 0007, 0047)는 파일명도 바꾼다. 워크로그 본문도 일괄 치환한다. 단 ADR 0055(이 문서) 자체는 결정 시점의 기록이라 "벼름"이라는 이름이 맥락 안에 그대로 등장한다.

## 결과

### 긍정적

- 한 결로 통일. 두 이름이 섞이지 않는다
- 새 기여자에게 byeorim 한 단어만 노출
- 어감, 발음, 검색성, 의미가 더 분명한 이름으로 출시 전 결을 잡는다

### 부정적 / 트레이드오프

- 일회성 마이그레이션 비용. 본문 1300+ 회 등장, 파일 140개 영향
- 외부에 이미 공유된 링크가 있다면 깨질 수 있음. 다만 오픈소스 공개 직전이라 외부 인용이 거의 없다
- 워크로그/ADR 본문을 갱신하는 결이 평소 "역사를 다시 쓰지 않는다"와 다르다. 다만 이번에는 이름이 모든 역사 기록에 박혀 있어 본문 갱신이 정합을 잇는 유일한 결

### 미래 묶임

- 차후 또 한번 이름을 바꾸는 결은 더 큰 비용을 부른다. 벼림이 마지막 이름이라는 결로 못 박는다
- 외부 인용(블로그, 발표 등)에 이전 이름이 남아 있어도 이 ADR이 단일 진실 소스로 동작한다
