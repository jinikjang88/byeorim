# ADR 0011. 인터랙티브 prompt 정책

- 상태: 채택
- 날짜: 2026-04-28
- 결정자: DevSmith

## 맥락

지금까지 벼림의 모든 명령어는 비인터랙티브였다. `byeorim prospect 쇼핑몰 만들어줘`나 `byeorim smelt order coupon`처럼 사용자가 인자를 직접 줘야 했다. 이 방식은 시니어 개발자(우선순위 3번)에게는 자연스럽지만, 1순위 사용자(비기술 창업자)에게는 큰 진입 장벽이다.

특히 smelt가 그렇다. 비기술 창업자가 카탈로그의 블럭 ID(`order`, `coupon`, `pg-integration` 등)를 알 길이 없다. 카탈로그 YAML 파일을 직접 열어 ID를 찾아 적어야 한다. CLAUDE.md 섹션 0의 사용자 우선순위와 정면으로 충돌한다.

ADR 0010이 인터랙티브 prompt 도입을 별도 ADR로 미뤘다. 이번 ADR이 그 자리를 채운다.

이번 결정의 범위는 정책이다. 라이브러리 선택, 인터랙티브 진입 방식, 한국어 정책, 테스트 가능성 네 가지를 정한다. 미래에 새 명령어가 들어와도 이 정책을 그대로 따른다.

## 검토한 옵션

### 결정 1. prompt 라이브러리

#### 옵션 A. @inquirer/prompts (modern modular)
- 장점: inquirer 저자들이 만든 현대적 모듈러 API. ESM-first. 필요한 prompt 종류만 import해 의존성 부담을 줄인다(`import { checkbox } from '@inquirer/prompts'`). TypeScript 타입 우수. 한글 렌더링 문제 없음
- 단점: classic inquirer보다 새로워서 커뮤니티 자료가 살짝 적다

#### 옵션 B. prompts (terkelg)
- 장점: 매우 가벼움. 단일 함수 API
- 단점: 활발히 유지보수 중인지 살짝 의문. 기능이 적어 미래에 더 복잡한 prompt(autocomplete, search)를 만들 때 모자랄 수 있음

#### 옵션 C. 자체 구현
- 장점: 의존성 0
- 단점: 화살표 키, raw mode, 멀티 라인 처리 같은 자리에서 직접 짜야 할 코드가 많다. 한 번 잘못 짜면 사용자 경험이 무너진다. 1순위 사용자가 가장 먼저 만나는 자리에 자체 구현은 위험

#### 옵션 D. classic inquirer
- 장점: 가장 익숙
- 단점: ESM 호환성 자리에서 잡음이 있었던 역사. @inquirer/prompts가 그 후속

### 결정 2. 인터랙티브 진입 방식

#### 옵션 A. 인자 누락 시 자동 인터랙티브 (implicit)
- 장점: 비기술 창업자가 가장 자연스러운 흐름. `byeorim smelt`만 치면 prompt가 뜬다
- 단점: 자동 동작이라 예측이 어려울 때가 있다. CI 환경에서 stdin이 닫혀있으면 곤란

#### 옵션 B. 명시 플래그 (--interactive)
- 장점: 명확한 의도
- 단점: 비기술 창업자가 `--interactive`를 알 가능성이 낮다. 1순위 사용자에게 한 단계 더 학습이 필요

#### 옵션 C. TTY 감지 기반 자동 전환
- 장점: 환경에 맞춰 자동
- 단점: 인자 누락 + TTY 없음 같은 자리에서 동작이 모호해짐. 명시적 처리가 줄어 디버깅이 어려워짐

### 결정 3. 첫 적용 단계

#### 옵션 A. smelt만 (이번 출시)
- 장점: 가장 필요한 자리부터. 학습 비용 분산
- 단점: 일관성이 살짝 약함

#### 옵션 B. 모든 단계 동시 (prospect, smelt, shape, ...)
- 장점: 일관된 사용자 경험
- 단점: 각 단계의 산출물 형식이 다 정해진 뒤가 자연스럽다. 지금은 prospect와 smelt만 형식이 있어 나머지는 prompt할 자리가 없다

#### 옵션 C. prospect와 smelt 둘 다
- 장점: 두 단계가 짝
- 단점: prospect는 이미 자유 텍스트 입력(자연어 한 마디)이라 인터랙티브 prompt가 추가하는 가치가 적다. 빈 입력 받아 다시 묻는 정도

### 결정 4. 메시지 언어와 식별자 표시

#### 옵션 A. 한국어 메시지, 식별자(블럭 ID, world ID)는 원래 형태 + 사람이 읽는 이름 함께
- 장점: 비기술 창업자에게 의미가 즉시 보이고, 식별자가 원래 형태라 다음 단계의 디버깅이 쉽다
- 단점: 화면이 살짝 길어짐

#### 옵션 B. 한국어 메시지, 식별자 숨김(이름만)
- 장점: 가장 친절
- 단점: 다음 단계나 에러 메시지에서 식별자가 등장할 때 사용자가 다시 매핑해야 함

#### 옵션 C. 영문 메시지
- 장점: 글로벌 일관성
- 단점: CLAUDE.md 섹션 0 사용자 우선순위 위배

### 결정 5. 테스트 가능성

#### 옵션 A. picker 함수를 의존성 주입(prospect의 어댑터 패턴과 같은 결)
- 장점: 단위 테스트가 mock picker로 결정적이고 빠르다. CLAUDE.md 섹션 4의 단위 테스트 5초 미만이 자연스럽게 지켜짐. ADR 0009의 어댑터 의존성 주입 정신과 일관
- 단점: API에 인자 하나가 더 들어감

#### 옵션 B. @inquirer/prompts를 직접 호출, 테스트는 stdin mock
- 장점: API 단순
- 단점: stdin mock은 비결정적 자리가 자주 생긴다. 테스트가 깨지기 쉬움

## 결정

### 결정 1: @inquirer/prompts (옵션 A)

`@inquirer/prompts` 패키지를 채택한다. 모듈러 import로 필요한 종류만 끌어쓰고, ESM 호환이 확실하다. 한글 렌더링 문제 없고 화살표 키와 검색 같은 미래 자리도 그대로 받쳐준다.

### 결정 2: 인자 누락 시 자동 인터랙티브 (옵션 A)

`byeorim smelt`처럼 인자가 누락되면 자동으로 인터랙티브 prompt를 띄운다. 1순위 사용자(비기술 창업자)가 가장 자연스럽게 만나는 흐름이다.

CI 환경 같이 stdin이 없는 자리에서는 prompt 라이브러리가 자체적으로 에러를 내고, 그 에러는 비인터랙티브로 인자 주는 길을 안내한다. CI 사용자는 인자를 명시하면 된다.

### 결정 3: 이번 출시는 smelt만 (옵션 A)

prospect는 이미 자유 텍스트 입력이라 인터랙티브 prompt가 추가하는 가치가 적다. shape, forge, temper, set, inspect는 산출물 형식이 정해진 뒤 각자 ADR로 인터랙티브 자리를 결정한다. 이번 ADR이 정한 라이브러리 선택과 진입 방식, 의존성 주입 패턴은 모든 미래 단계에 그대로 적용된다.

### 결정 4: 한국어 메시지 + 식별자 보존 (옵션 A)

prompt 텍스트, 안내, 검증 메시지 모두 한국어. 식별자(블럭 ID, world ID 등)는 원래 형태로 보존하고, 사람이 읽는 이름(name 필드)을 함께 보여준다.

블럭 선택 prompt 예시.

```
? 어떤 블럭을 만들고 싶으세요? (스페이스로 선택, 엔터로 확정)
  ◯ order: 주문 (구매자가 상품을 선택해 주문을 넣는다)
  ◯ payment: 결제 (PG 연동을 통한 결제 처리)
  ◯ coupon: 쿠폰 (할인 코드 발급과 사용)
  ...
```

식별자(order, payment)가 옆에 보여 사용자가 다음 단계 메시지에서 같은 ID를 만나도 매핑이 자연스럽다.

### 결정 5: picker 함수 의존성 주입 (옵션 A)

`interactiveSmelt({ cwd, pickBlocks })`처럼 picker를 인자로 받는다. 기본값은 `@inquirer/prompts`의 `checkbox`를 호출하는 함수. 단위 테스트는 mock picker를 주입한다.

ADR 0009의 AI 어댑터 의존성 주입과 같은 결이다. 두 자리 모두 외부 I/O(LLM 호출, stdin 입력) 의존성을 인자로 추출해 결정성과 테스트 가능성을 확보한다.

## 결과

### 긍정적
- 1순위 사용자 진입 장벽이 한 단계 낮아진다. `byeorim smelt`만 치면 카탈로그에서 블럭을 골라준다
- 의존성 주입이라 단위 테스트가 결정적이고 빠르다. CLAUDE.md 섹션 4의 5초 미만 약속이 흔들리지 않는다
- 비인터랙티브 흐름이 그대로 유지된다. CI/스크립트는 인자 주면 기존처럼 동작
- 식별자 보존으로 다음 단계의 메시지와 결을 맞췄다. 사용자가 인터랙티브 picker에서 본 ID를 다른 자리에서 다시 만나도 어색하지 않다

### 부정적 / 트레이드오프
- 의존성이 한 패키지(@inquirer/prompts) 늘었다. 모듈러 import라 무게는 가볍지만 0은 아니다
- 인자 누락 시 자동 인터랙티브는 CI에서 prompt가 멈출 위험을 안고 있다. CI 사용자가 명시적으로 인자를 줘야 하는 자리가 늘었다. 다만 에러 메시지가 인자 주는 길을 안내하므로 사용자가 막막하지 않다
- 식별자와 이름을 함께 보여주면 화면이 살짝 길어진다. 카탈로그가 큰 도메인은 화면이 한참 스크롤될 수 있다. 미래에 검색 기반 필터링을 도입하면 자연스럽게 해결된다

### 미래 묶임
- @inquirer/prompts가 첫 prompt 라이브러리다. 다른 라이브러리로 바꾸려면 ADR이 필요하다
- 인자 누락 → 자동 인터랙티브 동작은 모든 명령어의 표준이다. 명시 플래그로 바꾸려면 ADR이 필요하다
- picker 의존성 주입은 모든 인터랙티브 명령어의 표준 패턴이다. 미래의 prospect/shape/forge/temper/set/inspect 인터랙티브 코드도 같은 결을 따른다
- 메시지 한국어와 식별자 보존은 모든 prompt의 표준이다. 영문 prompt는 도입하지 않는다(절대 금지선과 결이 같다, CLAUDE.md 섹션 0)
