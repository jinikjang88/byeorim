# ADR 0026. Prospect 7항목 동행 질문과 다이어리

- 상태: 채택
- 날짜: 2026-05-03
- 결정자: DevSmith
- 관계: ADR 0008의 결정 2를 부분 갱신한다

## 맥락

ADR 0008이 prospect의 의도 추출을 (what, who, why) 세 키로 정했다. 그 선택의 이유는 옵션 C(깊은 구조화)가 비기술 창업자에게 첫 단계 부담이 크다는 우려였다. 실제 첫 사용자 테스트로 두 가지가 드러났다.

첫째, 한 줄 자유 텍스트 입력만으로는 사용자가 자기 서비스를 다층으로 그려보기 어렵다. AI가 한 문장 의도만 뽑고 끝낸다. 다음 단계(smelt의 블럭 선택)에서 사용자에게 의미 있는 발판이 안 된다.

둘째, who와 why가 비어도 된다는 약속은 좋았으나 사용자에게 그 자리가 보이지 않으면 답할 시도조차 안 한다. 목록이 출력되며 생각하며 적는 것과 목록이 나오지도 않고 안 적는 것은 천차만별이다.

답을 강요하지 않는 동행 톤(CLAUDE.md 절대 금지선 2번, ADR 0003 결정 2)은 그대로다. 다만 첫 단계 발판을 두텁게 해야 한다. 기술 용어로는 "구조화"이지만 사용자 입장에서는 "그려볼 자리"가 더 잘 맞는다.

## 검토한 옵션

### 결정 1. 추출 항목 개수

#### 옵션 A. 3항목 유지 (what, who, why)
- 장점: 변경 없음. 사용자에게 가장 가벼운 첫 만남
- 단점: 다음 단계가 의미 있게 사고할 발판이 얇다. 운영 관점이 아예 빠짐

#### 옵션 B. 6항목 (5W1H, how 한 칸)
- 장점: 육하원칙 표준. 한국어 사용자에게 익숙한 틀
- 단점: 비기술 창업자 1순위 사용자에게 핵심인 "어떻게 관리하는가"가 사용 흐름과 한 칸에 묶여 묻힌다

#### 옵션 C. 7항목 (5W + how_use + how_manage)
- 장점: 운영 관점이 사용자 흐름과 분리되어 두 자리에서 각각 묻힌다. 카페 사장님, 학원 원장님 1순위 사용자에게 핵심
- 단점: 7번 prompt가 길다. 사용자 인내력 부담

### 결정 2. 입력 방식

#### 옵션 A. 한 줄 자유 텍스트 + AI 추출 (현행)
- 장점: 사용자 입력 부담 최소
- 단점: AI 추출 정확도 변수가 큼. 빈 자리가 사용자에게 안 보임

#### 옵션 B. 자유 단락 + AI 추출 + 빈 칸 보충
- 장점: 한 번에 풀어쓰기와 보충이 모두 가능
- 단점: 단락 쓰기를 부담스러워 하는 비개발자 사용자에게 진입 장벽

#### 옵션 C. 7항목 차례 질문
- 장점: 한 줄씩 묻어 쓰기 부담이 작다. 빈 자리도 명시적으로 본다
- 단점: 7번 입력이 이어진다

### 결정 3. 빈 항목 처리

#### 옵션 A. 진행 차단
- 장점: 모든 자리가 채워져야 다음 단계
- 단점: 답을 강요하지 않는 동행 톤(ADR 0003)과 충돌

#### 옵션 B. 빈 채로 진행
- 장점: 동행 톤 유지
- 단점: 빈 자리가 잊혀짐

#### 옵션 C. 빈 채로 진행 + 다이어리 자동 적재
- 장점: 동행 톤 유지하면서 빈 자리가 다이어리에 질문으로 살아남는다. 나중에 사용자가 답 적을 자리 마련
- 단점: 다이어리에 prospect 외 다른 출처도 섞일 수 있음(향후 정리 필요)

### 결정 4. 키 언어

#### 옵션 A. 영문 키 (what/who/...)
- 장점: ADR 0008의 결정과 같은 결. 절대 금지선 6번(벤더 무관) 유지. AI 어댑터가 모델 무관하게 같은 키를 쓴다
- 단점: 비개발자에게 영문 키가 직접적이지 않다

#### 옵션 B. 한국어 키 (무엇/누가/...)
- 장점: 사용자에게 친근
- 단점: schema 마이그레이션 비용. YAML 비교/diff가 다국어 의존이 됨. 미래 다국어 사용자 대응이 어려움

## 결정

### 결정 1: 7항목 채택 (옵션 C)

`what`, `who`, `when`, `where`, `why`, `how_use`, `how_manage`. 운영 관점을 사용 관점과 분리해 1순위 사용자(카페 사장님, 학원 원장님)에게 핵심인 "어떻게 관리하는가" 자리를 명시한다.

### 결정 2: 7항목 차례 질문 (옵션 C)

`@inquirer/prompts`의 `input`으로 7번 차례 묻는다. 각 질문은 한국어 라벨과 한국어 입력 예시(`(예: ...)`)를 함께 보인다. 빈 답 허용.

### 결정 3: 빈 채로 진행 + 다이어리 자동 적재 (옵션 C)

빈 항목이 있으면 그대로 intent.yml에 빈 문자열로 기록하고 동시에 `.beoreum/project/diary.md`에 질문 형식으로 추가한다. 머리에 날짜와 단계를 적어 추적 가능하게.

### 결정 4: 영문 키 유지 (옵션 A)

intent.yml과 AI 어댑터의 키는 영문 그대로. CLI 출력에서 한국어 라벨을 함께 보여 사용자 친근함을 챙긴다.

### intent.yml 새 형식 (schema_version 2)

```yaml
schema_version: 2
created_at: 2026-05-03T12:00:00.000Z
user_answers:
  what: 동네 빵집 단골 주문 앱
  who: 카페 단골 손님과 사장님
  when: ''
  where: 손님은 모바일, 사장님은 매장 태블릿
  why: 전화 주문이 자꾸 끊겨서
  how_use: QR로 메뉴 보고 주문
  how_manage: ''
source: template:commerce
extracted:
  what: 동네 빵집 단골 주문 앱
  who: 카페 단골 손님과 사장님
  when: ''
  where: 손님은 모바일, 사장님은 매장 태블릿
  why: 전화 주문이 자꾸 끊겨서
  how_use: QR로 메뉴 보고 주문
  how_manage: ''
unanswered:
  - when
  - how_manage
reality_check_status: pending
```

`user_answers`는 사용자 입력 그대로, `extracted`는 AI를 거친 결과. 두 자리를 두면 미래 어댑터가 정규화나 정리를 해도 사용자 원본이 보존된다. `unanswered`는 빈 항목 키 목록으로 다음 단계가 다시 묻지 않게 안내.

### 다이어리 추가 형식

```markdown
## 2026-05-03 prospect에서 미뤄둔 질문

- when: 언제 주로 쓰는 서비스일까요? 하루 중 시점, 계절, 특정 사건 직전 같은 시간축이 있나요?
- how_manage: 운영자는 어떻게 관리할까요? 매일/매주 어떤 일을 하실지 떠올려보세요.
```

`appendFileSync`로 기존 내용 끝에 추가. 사용자가 미리 적어둔 메모는 보존.

## 결과

### 긍정적
- 비기술 창업자가 자기 서비스를 7개 자리로 그려본다. 다음 단계가 두텁게 받는다
- 빈 자리도 사용자에게 보인다. 그리고 다이어리로 자연스럽게 흘러간다(동행 톤)
- 운영 관점(how_manage)이 별도 자리를 가져 1순위 사용자(카페 사장님, 학원 원장님)에게 핵심인 자리가 묻히지 않는다
- ADR 0008의 결정 1(한 파일), 결정 3(source), 결정 4(reality_check_status)는 그대로 살아있다. amend 형식이라 마이그레이션이 가볍다

### 부정적 / 트레이드오프
- 사용자가 7번 prompt를 통과해야 한다. 첫 만남 부담이 ADR 0008 결정보다 크다. 빈 답 허용으로 그 부담을 낮추지만 화면 길이 자체는 늘어난다
- intent.yml schema_version이 1에서 2로 올라간다. 1을 읽는 마이그레이션은 두지 않는다(프로토타입 단계, 실 사용자 0)
- AI 어댑터 인터페이스가 바뀐다. extractIntent의 입력이 string에서 ProspectAnswers 객체로. 호환성 깨짐

### 미래 묶임
- 7항목 키 이름은 표준이다. 변경하려면 schema_version을 올리고 새 ADR
- 다이어리 추가 형식(`## YYYY-MM-DD prospect에서 미뤄둔 질문`)도 표준. 다른 단계가 다이어리에 적을 때 같은 결의 머리를 쓴다(향후 ADR로 명시화)
- ProspectAnswers의 키 7개와 ExtractedIntent의 키 8개(7 + suggested_template)가 짝. 한쪽 변경 시 다른 쪽도 ADR로 갱신

## 링크
- 갱신 대상: ADR 0008 (intent.yml 형식, 결정 2 부분 갱신)
- 짝 결정: ADR 0009 (AI 어댑터 인터페이스, extractIntent 시그니처 영향)
- 동행 톤: ADR 0003 결정 2 (답을 강요하지 않는 자리)
- 인터랙티브 패턴: ADR 0011 결정 5 (askInput 의존성 주입의 정신을 askAnswers로 잇는다)
- 관련 정책: CLAUDE.md 섹션 2(절대 금지선 2번), 섹션 5(다이어리), 섹션 8(데이터 무관성)
