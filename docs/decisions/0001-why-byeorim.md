# ADR 0001. 왜 벼림인가 (프로젝트 이름 결정)

- 상태: 채택
- 날짜: 2026-04-27
- 결정자: DevSmith

## 맥락

이 프로젝트는 Forge Protocol이라는 이름으로 시작됐다. 대장장이 메타포(Smelt, Shape, Forge, Temper, Inspect)를 코드 도구에 도입한다는 발상에서 출발한 이름이다. CLI v0.1.0이 GitHub 레포에 커밋된 상태였고, 일부 문서와 5단계 명세도 그 이름으로 작성되어 있었다.

이름을 바꾸기로 결정한 직접적 계기는 두 가지였다.

첫째, 2026년 4월 기준으로 SDD(Spec-Driven Development) 진영이 빠르게 형성되고 있다는 사실을 확인했다. GitHub Spec Kit, OpenSpec, AWS Kiro, Tessl 등이 비슷한 자리("코드 이전에 설계를 강제")를 노리고 있었다. "Forge"라는 단어는 이미 영어권 개발 도구에서 흔하다(Forge of Empires, GitHub Forge, Adobe Forge 등). 차별화가 약했다.

둘째, "Forge Protocol"이라는 이름이 이 프로젝트의 1순위 사용자(비기술 창업자)에게 가닿지 않는다는 점이다. "Protocol"은 기술 용어이고, "Forge"도 영어 화자에게나 즉시 통한다. 카페 사장님, 학원 원장님이 이 이름을 보고 자기 도구라고 느낄 가능성은 낮다.

추가로 확인된 사실. 단일 영어 명사로 npm과 GitHub 양쪽이 비어있는 후보를 찾기는 거의 불가능했다. anvil, smithy, ingot, tongs, forja, quench 등 13개 후보를 조사했고, 대부분 npm 또는 GitHub 점유 상태였다. 살아있는 패키지와 충돌하거나 변형을 사용해야 하는 상황이었다.

## 검토한 옵션

### 옵션 A. Forge Protocol 유지
- 장점: 기존 코드와 문서를 다시 작성할 필요 없음. 영어권 개발자가 첫눈에 메타포를 이해
- 단점: 차별화 약함. 다른 SDD 도구와 구분 어려움. 비기술 창업자에게 가닿지 않음. "Forge"라는 단어의 보편성으로 인해 검색 노출과 브랜드 형성이 어려움

### 옵션 B. 새 영문 이름 (Smithwork, Anvilcode 등)
- 장점: 영어권 즉시 통함. 글로벌 시장 진입 즉시성
- 단점: 단일 영문 명사는 npm/GitHub 점유 거의 다 막혀있음. 우회 이름(forja-cli, smithyjs 등)을 쓰면 그 자체가 약함의 신호. 한국 정체성과 단절

### 옵션 C. 한국어 발음을 영문화 (Byeorim, Beori 등)
- 장점: 유일성 확보. Toss, Kakao, Naver의 입증된 길. DevSmith 한국 정체성과 연결. npm/GitHub 청정. 외국인에게는 새 단어처럼 들리고 한국인에게는 즉시 의미 통함
- 단점: 영어권 첫 진입 시 학습 곡선. 외국인은 이름의 어원을 알기 위해 한 번의 설명이 필요함

## 결정

옵션 C를 채택한다. 프로젝트 이름은 Byeorim(벼림)이다.

벼림은 우리말 "벼리다"의 명사형이다. 무딘 칼날을 두드리고 갈아 날을 세우는 일을 뜻한다. 막연한 쇳덩어리를 쓸 수 있는 도구로 만드는 과정이다. 이 프로젝트가 사용자에게 하는 일이 정확히 그것이다. 막연한 아이디어를 코드 이전에 볼 수 있는 블럭으로 만들고, 그 시장에서 살아남을 수 있을지를 함께 본다.

DevSmith와 벼림의 관계는 이름 자체에 박혀있다. DevSmith가 "코드를 벼리는 대장장이"라면 벼림은 "그 인장이 새기는 동작"이다. 사람의 정체성과 행위의 정체성을 분리했다. 도구는 만든 사람보다 오래 살아야 하기 때문이다.

이름 후보 검증에서 결정적이었던 것은 npm과 GitHub 양쪽이 청정한 거의 유일한 후보가 byeorim이었다는 점이다. 도메인 결정에서 *유일성*은 양보 불가의 자산이다.

## 결과

### 긍정적
- 프로젝트가 다른 SDD 도구와 즉시 구분된다
- 한국 정체성이 이름에 박혀있어 한국 1차 GTM에 강력하다
- npm, GitHub 모두 청정해서 표준 패키지명 확보 가능
- DevSmith라는 운영자 인장과 자연스럽게 연결된다
- 외국인에게는 신조어처럼 들려서 추가 설명이 필요하지만, 그 설명 자체가 브랜드 스토리가 된다

### 부정적 / 트레이드오프
- 영어권 개발자의 첫 진입 시 학습 곡선이 존재한다. "Byeorim이 뭔지" 한 번은 설명해야 한다
- Forge Protocol 시절 작성된 코드와 문서를 모두 마이그레이션해야 한다(.forge/ 디렉토리는 .byeorim/으로, bin/forge.js는 bin/byeorim.js로, 메타포 명령어도 갱신)
- 기존 forge-protocol 레포의 리네임 또는 신규 레포 결정이 필요하다(별도 결정으로 보류)
- 한글 어원이 통하지 않는 비한국어권 사용자에게는 이름 자체로 의미를 전달하지 못한다

### 미래 묶임
- 이 결정 이후 모든 도구·문서·메타포는 "벼림" 정체성을 따른다
- 차후 글로벌 확장 시 영어 부제(예: "Byeorim, the design-first AI collaboration protocol") 같은 보조 카피가 필요할 수 있다. 그것은 그때 별도 ADR로 결정한다
- "Byeorim" 표기는 표준이다. "byeoreum", "Beori" 같은 다른 표기는 채택하지 않는다

## 링크
