## 다섯 번째 세션의 목표

오늘 사용자가 외부 AI 응답 결에서 YAML 깨짐 결을 두 번 부딪혔다(temper의 reason 따옴표, forge의 콜론). 파서 결을 친절히 안내하는 결(PR #9)을 박았지만 원천적으로 외부 AI가 YAML을 안 깨도록 결을 잡는 결이 더 자연스럽다.

또 프롬프트 결에서 `──── 가로줄` 바로 뒤에 본문이 붙어 있어 사용자가 복사할 때 시각적 결이 흐려진다는 결을 사용자가 짚었다. 한두 줄 개행 결을 모든 단계에 박는다.

## 변경 사항

### 손댄 파일

- packages/cli/src/{smelt,shape,forge,temper,inspect,prospect}-prompt.js — HEADER에 `──── 가로줄` 뒤 1줄 공백, FOOTER에 1줄 공백 박음. 6개 모두 같은 결로
- packages/cli/src/{smelt,shape,forge,temper,inspect}-prompt.js — 규칙 섹션 끝에 "YAML 따옴표 규칙" 한 줄 박음. 값에 콜론(`:`), `#`, 따옴표 결이 있으면 작은따옴표로 감싸달라는 결 + 도메인-맞춤 예시(forge는 endpoint 결, temper는 받침 결, inspect는 finding detail 결 등)
- packages/cli/src/prospect-prompt.js — OUTPUT_GUIDE에 "## YAML 따옴표 규칙 (중요)" 섹션 박음. catalog 자체가 YAML 본문이라 별도 섹션 결로 강조. OUTPUT_GUIDE 끝 trailing newline도 한 결 트림해 닫는 marker 앞 공백을 1~2줄로 정합

## 배운 점

YAML 따옴표 규칙을 6개 프롬프트에 같은 결로 박는 결이 자연스러웠다. 5개(smelt/shape/forge/temper/inspect)는 "응답 형식 안내" 섹션의 규칙 bullets에 한 줄 추가. prospect만 raw YAML 출력이라 별도 "## YAML 따옴표 규칙 (중요)" 섹션으로 강조. 각 프롬프트의 예시 결도 도메인-맞춤(forge=endpoint, temper=받침/조사, inspect=N+1 쿼리)으로 박아 외부 AI가 결을 잘 이해.

HEADER에 트레일링 빈 줄, FOOTER에 리딩 빈 줄을 박는 결로 가로줄 위아래 시각 결을 살렸다. 사용자가 가로줄 사이를 드래그 복사할 때 본문이 가로줄에 붙어있던 결이 풀어짐. 6개 모두 같은 결로 정합.

prospect의 OUTPUT_GUIDE 끝에 trailing newline이 있어 닫는 marker 앞에 3줄 공백이 박혔던 결을 발견. 다른 5개는 `[...].join('\n')` 결로 body가 trailing newline 없는데 prospect만 OUTPUT_GUIDE 자체가 \n으로 끝나는 결이라 한 결 더 박힌다. 트림해 1~2줄로 정합.

JS 문자열 안에서 작은따옴표 결을 노출하려면 큰따옴표 결로 박는 결이 깔끔. 기존 코드는 single-quote 결로 통일됐지만 이번 규칙 결은 안에 작은따옴표 예시가 있어 double-quote 결로 박았다. Prettier가 singleQuote=true지만 안에 single quote 결이 있으면 double 유지(자동 결).

## 알아둘 것

- 가로줄 위아래 공백 결은 opening 1줄, closing 1~2줄. 6개 모두 정합. 사용자가 복사할 때 본문이 가로줄에 안 붙음
- YAML 따옴표 규칙 결은 외부 AI에게 보내는 본문 안에 들어감(HEADER/FOOTER 사이). 사용자는 마크다운 결로 가로줄 위 안내만 보고, 외부 AI는 가로줄 안 본문에서 규칙 결을 받음
- prospect의 OUTPUT_GUIDE 끝 trailing newline 트림으로 닫는 marker 앞 공백이 2줄. 다른 5개도 2줄. 정합
- 차후 새 프롬프트를 박을 때 같은 패턴 결을 따라가는 결. HEADER 트레일링 1줄 + FOOTER 리딩 1줄 + 규칙 끝에 YAML 따옴표 결
