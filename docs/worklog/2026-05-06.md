## 배운 점

forge ADR 0023의 결을 그대로 옮기니 temper 어댑터 통합이 자연스러웠다. extractSchema가 두 자리(mock generic placeholder + claude 도메인 추론)로 갈라진 결을 fillTestCode도 그대로 따라간다(mock 언어 무관 의도 + claude 언어별 프레임워크 코드). 두 어댑터의 책임 분리가 같은 결로 박혀 사용자가 한 번 익히면 두 번째 자리에서 같은 시각을 적용할 수 있다.

mock의 한 줄(`// TODO: <given>을 준비하고 <when>을 호출해 <then>을 검증한다`)이 `//` 주석 마커라 python에서는 `#`로 바꿔야 어울린다. 한 글자 차이라 무겁지 않지만 미세한 어색함이 있다. mock의 책임이 인터페이스 검증과 결정성이라(섹션 8 데이터 무관성) 언어별 분기는 claude의 자리로 미루는 결이 옳다고 판단. 이번 출시는 결정적이라 단위 테스트가 LLM 호출 없이 끝까지 돈다.

claude의 TEST_CODE_SYSTEM_PROMPT가 architecture.language 표를 system prompt에 박는다. 미래에 프레임워크 변경 시 prompt 변경 자리가 한 곳에 모인다. 흔한 프레임워크(node:test/JUnit/pytest)라 안정적. 프레임워크 표가 코드(packages/cli/src/temper.js)에 박히면 변경 자리가 두 곳으로 갈라지는데, prompt에만 두니 한 자리. 미래에 generator(set 단계)가 같은 표를 봐야 하면 prompt-helpers 같은 자리로 정리하는 결이 자연스러울 자리.

runTemper가 architecture.yml을 처음 읽는 자리가 됐다. forge처럼 옵셔널 자리(어댑터 없으면 안 읽음)로 두니 후행 호환이 자연스럽다. `existsSync(archFile)` 가드로 architecture.yml이 없을 때도 graceful. catalog.yml도 같은 결로 옵셔널(블럭 도메인 정보가 있으면 어댑터에 전달, 없어도 안전).

mock의 GWT 텍스트 인용에서 `${given}을 준비하고`처럼 조사가 어색해졌다(`을`이 받침 없는 텍스트 뒤에 붙으면 `를`이 자연스러움). 한국어 조사 자동 처리는 미래 자리. 이번 출시는 결정성과 결을 우선.

claude 어댑터의 메서드가 일곱이 됐다(extractIntent, generateCatalog, generateRealityCheck, recommendBlocks, recommendArchitecture, extractSchema, fillTestCode). 인터페이스가 자라면서 한 자리에서 변경이 다른 자리에 영향을 안 주는 결이 살아남았다. 객체 인자 패턴과 옵셔널 메서드 결정 둘이 같이 작용한 결과.
