## 배운 점
- @anthropic-ai/sdk 0.91.1의 messages.parse가 output_config.format = { type: 'json_schema', schema } 인자를 받아 응답을 자동 파싱해 message.parsed_output에 채운다. 별도 try/catch 파싱 자리가 거의 사라졌다. ADR 0023의 Schema 부분집합을 그대로 schema로 넘길 수 있어 두 ADR이 한 형식으로 묶였다
- SDK의 APIError 계열(AuthenticationError, RateLimitError 등)은 생성자 네 번째 인자로 Headers-like 객체(get 메서드)를 요구한다. 테스트에서 가짜 에러를 던질 때 빈 객체 `{}` 대신 `new Headers()`를 넘겨야 한다. 처음 헷갈렸다. 두 번 안 헷갈리려면 적어둔다
- claude-opus-4-7 기본 모델은 claude-api 스킬의 강한 권고였다. "비용을 줄이려고 함부로 다운그레이드하지 말라, 그건 사용자 결정이다"의 정신을 ADR 0024 결정 4에 그대로 박았다. 사용자가 BYEORIM_AI_MODEL로 명시적으로 바꿀 자리만 열어둔다
- 의존성 주입 패턴이 다섯 번째 적용이다(ADR 0009 adapter, 0011 picker, 0019 BackendChoices, 0022 runCommand, 0024 client). 같은 결의 패턴이 다섯 자리에 반복되는 건 좋은 신호다. CLAUDE.md 섹션 8 "패턴 일관성"이 코드에서 자연스럽게 나타나는 자리

## 아직 열려있는 것
- 실제 Claude API 호출을 한 e2e smoke 테스트는 이번 출시에 없다. SDK가 키와 네트워크를 요구해서 CI에서 결정성을 보장할 수 없다. mock client 주입으로 인터페이스와 응답 파싱은 모두 검증하지만, 실제 응답이 정말 한국어 도메인을 잘 추론하는지는 사용자가 손으로 확인하는 자리
- prompt caching 적중률은 측정하지 않는다. SDK 응답의 usage.cache_read_input_tokens 같은 자리가 있지만 텔레메트리 정책(절대 금지선 7번)과 묶인 자리라 별도 ADR 후보
- 비용 추적도 미래 자리. 호출 횟수와 토큰 합산을 사용자가 보고 싶을 때, 절대 금지선 7번(텔레메트리 금지)과의 균형을 ADR로 결정
- GPT, Gemini 같은 다른 벤더 어댑터는 ADR 0024와 같은 패턴 재사용 예상. select.js의 ADAPTERS 표만 갱신하면 된다
- extractSchema의 system 프롬프트가 영어 도메인에서도 잘 동작하는지는 검증되지 않았다. 한국어 도메인 위주로 시작했으므로 영어 카탈로그가 들어오면 다시 본다
- README와 CLI에 BYEORIM_AI_ADAPTER, ANTHROPIC_API_KEY 환경 변수 안내 추가는 다음 PR 자리

# 후속 세션 (2026-04-29, 외부 브릿지 baseURL 노출)

## 이번 세션의 목표
ADR 0024가 박은 Claude 어댑터를 키 없이도 쓸 수 있도록 SDK의 baseURL 옵션을 ANTHROPIC_BASE_URL 환경 변수로 노출한다. 사용자 결정으로 옵션 A(baseURL 노출)로 진행. Claude Code 같은 브릿지 서버를 직접 띄울 사용자나, API 키 발급이 부담스러운 비기술 창업자 사용자가 첫 진입 자리에서 마찰을 덜도록 한다. 별도 어댑터(claude-code) 신설은 사용자 신호가 나타나면 미래 ADR로 본다.

## 변경 사항
- `docs/decisions/0025-ai-base-url-for-bridge-compatibility.md` 신설. 결정 셋. (1) 환경 변수는 ANTHROPIC_BASE_URL 단일(SDK 표준 따름). (2) baseURL이 있고 키가 없으면 placeholder 키(`byeorim-bridge-placeholder`)로 SDK 인스턴스화하고 통과. (3) 별도 claude-code 어댑터는 만들지 않음
- `packages/ai/src/claude.js` 갱신. `createClaudeAdapter`에 `baseURL` 인자 추가. 주어지면 `new Anthropic({ apiKey, baseURL })`. `client`가 명시 주입되면 baseURL은 무시(ADR 0024 결정 7의 의존성 주입 정신 보존)
- `packages/ai/src/select.js` 갱신. claude 분기를 `buildClaudeAdapter()`로 분리. 환경 변수 두 개(ANTHROPIC_API_KEY, ANTHROPIC_BASE_URL) 표대로 분기. 키도 baseURL도 없으면 두 경로(키 발급, 브릿지 사용)를 모두 안내하는 한국어 에러
- `bin/byeorim.js` 갱신. 도움말에 ANTHROPIC_BASE_URL 줄 추가. 예시도 직접 호출 / 브릿지 경유 두 가지로 풀어 적음
- `README.md` "AI 어댑터 설정" 절을 두 경로로 분리. "경로 1. Anthropic API 키로 직접 호출"과 "경로 2. Claude Code 등 브릿지 서버로 호출". 한 흐름의 비용이 일반적으로 1달러 미만이라는 추정도 함께 적음. 외부 브릿지 도구는 보증하지 않음을 명시

## 추가/수정된 테스트
- `tests/unit/ai-select.test.js` 갱신. `withEnv` 헬퍼에 ANTHROPIC_BASE_URL 키 추가. 한 케이스(키 없음 에러) 메시지 정규식을 두 경로 안내에 맞춰 갱신. 새 케이스 두 개. 첫째, baseURL만 있어도 claude 어댑터 만들기. 둘째, baseURL과 키 둘 다 있을 때 어댑터 만들기
- `tests/unit/ai-claude.test.js` 갱신. 새 케이스 한 개. baseURL과 client가 함께 주입되면 client가 우선(ADR 0024 결정 7 정신 보존). 직접 검증은 client.captured 호출 횟수
- 전체 단위 테스트 254 → 257로 늘었다. 모두 통과. 5초 미만 약속 유지

## 배운 점
- `@anthropic-ai/sdk`의 `Anthropic` 생성자는 baseURL을 옵션으로 받아 그쪽 서버로 호출을 보낸다. 이 한 자리만 노출하면 외부 브릿지 호환이 끝난다. 별도 어댑터를 만들거나 SDK를 우회할 필요가 없다. 절대 금지선 6번(벤더 무관)이 SDK 자체의 추상화로 자연스럽게 보존되는 자리
- baseURL이 SDK에 정확히 도달하는지 단위 테스트로 직접 보는 자리는 까다로움. ESM module mock이 가능하지만 SDK의 모든 export를 흉내 내야 해 fragile. 실용적인 답은 코드 단순화(select.js의 claude 분기 11줄)와 코드 리뷰. 단위 테스트는 분기 표 검증과 의존성 주입 약속 보존만 봄. SDK의 baseURL 동작 자체는 SDK 책임으로 신뢰
- placeholder 키 패턴은 두 자리에서 등장한다. 키 없이 baseURL만 있을 때 SDK 인스턴스화를 위한 자리(select.js)와, ADR 0024 결정 7의 결정성 약속을 위한 자리(테스트가 'sk-test'를 넘기는 자리). 같은 결의 패턴이 두 곳에 반복됨. 미래에 SDK가 키 형식 검증을 강화하면 한 자리만 갱신
- README의 비용 한 줄("일반적으로 1달러 미만") 추가가 사용자 입장에서 가장 큰 신호다. ADR 0024 결정 4가 claude-opus-4-7을 기본으로 박았지만 사용자는 모델 이름에서 비용을 추정하지 못한다. 막연한 두려움이 가장 큰 진입 장벽이라는 이전 세션의 인식이 한 줄 문서로 옮겨졌다

## 아직 열려있는 것
- 별도 claude-code 어댑터(Claude Code SDK 또는 subprocess 호출)는 미래 자리. 첫 비기술 창업자 사용자가 "브릿지 띄우는 게 너무 어려워요"라고 손드는 순간 ADR로 다시 본다. 미리 만들어두지 않음
- baseURL이 있을 때 SDK 호출이 실제로 그쪽으로 가는지의 e2e 검증은 이번 출시에 없음. 사용자가 손으로 확인하는 자리. CI 결정성 문제로 mock 서버 띄우는 통합 테스트는 보류
- 실제 사용 가능한 외부 브릿지 도구의 README 링크는 README에 박지 않음. 외부 프로젝트가 활발히 변하고 있어 우리가 보증할 수 없는 자리. 사용자가 검색해서 고른다. 만약 표준이 자리잡으면 그때 한 도구를 안내
- ANTHROPIC_BASE_URL과 ANTHROPIC_API_KEY가 둘 다 설정된 경우 SDK 동작 우선순위(baseURL이 우선시됨)는 README에 한 줄로만 적음. SDK 버전이 바뀌면 다시 확인 필요
- README의 "6단계" 표가 ADR 0006 이후 7단계로 확장됐는데 이번 PR에도 안 다뤘음. 다음 자리
