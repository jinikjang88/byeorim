## 배운 점
- @anthropic-ai/sdk 0.91.1의 messages.parse가 output_config.format = { type: 'json_schema', schema } 인자를 받아 응답을 자동 파싱해 message.parsed_output에 채운다. 별도 try/catch 파싱 자리가 거의 사라졌다. ADR 0023의 Schema 부분집합을 그대로 schema로 넘길 수 있어 두 ADR이 한 형식으로 묶였다
- SDK의 APIError 계열(AuthenticationError, RateLimitError 등)은 생성자 네 번째 인자로 Headers-like 객체(get 메서드)를 요구한다. 테스트에서 가짜 에러를 던질 때 빈 객체 `{}` 대신 `new Headers()`를 넘겨야 한다. 처음 헷갈렸다. 두 번 안 헷갈리려면 적어둔다
- claude-opus-4-7 기본 모델은 claude-api 스킬의 강한 권고였다. "비용을 줄이려고 함부로 다운그레이드하지 말라, 그건 사용자 결정이다"의 정신을 ADR 0024 결정 4에 그대로 박았다. 사용자가 BEOREUM_AI_MODEL로 명시적으로 바꿀 자리만 열어둔다
- 의존성 주입 패턴이 다섯 번째 적용이다(ADR 0009 adapter, 0011 picker, 0019 BackendChoices, 0022 runCommand, 0024 client). 같은 결의 패턴이 다섯 자리에 반복되는 건 좋은 신호다. CLAUDE.md 섹션 8 "패턴 일관성"이 코드에서 자연스럽게 나타나는 자리

## 아직 열려있는 것
- 실제 Claude API 호출을 한 e2e smoke 테스트는 이번 출시에 없다. SDK가 키와 네트워크를 요구해서 CI에서 결정성을 보장할 수 없다. mock client 주입으로 인터페이스와 응답 파싱은 모두 검증하지만, 실제 응답이 정말 한국어 도메인을 잘 추론하는지는 사용자가 손으로 확인하는 자리
- prompt caching 적중률은 측정하지 않는다. SDK 응답의 usage.cache_read_input_tokens 같은 자리가 있지만 텔레메트리 정책(절대 금지선 7번)과 묶인 자리라 별도 ADR 후보
- 비용 추적도 미래 자리. 호출 횟수와 토큰 합산을 사용자가 보고 싶을 때, 절대 금지선 7번(텔레메트리 금지)과의 균형을 ADR로 결정
- GPT, Gemini 같은 다른 벤더 어댑터는 ADR 0024와 같은 패턴 재사용 예상. select.js의 ADAPTERS 표만 갱신하면 된다
- extractSchema의 system 프롬프트가 영어 도메인에서도 잘 동작하는지는 검증되지 않았다. 한국어 도메인 위주로 시작했으므로 영어 카탈로그가 들어오면 다시 본다
- README와 CLI에 BEOREUM_AI_ADAPTER, ANTHROPIC_API_KEY 환경 변수 안내 추가는 다음 PR 자리

## 변경 사항
- `README.md`에 "AI 어댑터 설정" 절 추가. 기본은 mock이라 비용/네트워크 호출 없음을 먼저 알리고, 실제 LLM 사용 시 환경 변수 표와 두 가지 실행 예시를 둠. 키 없이 claude를 켜면 한국어 안내로 멈춘다는 점도 한 줄로 적음. ADR 0024 링크 첨부
- `bin/beoreum.js`에 `program.addHelpText('after', ...)` 추가. `beoreum --help` 출력 끝에 환경 변수 세 줄과 실행 예시 두 줄, README 절 안내가 붙음. 기존 명령어 테이블은 손대지 않음

## 추가/수정된 테스트
- 없음. README는 순수 문서, addHelpText는 정적 문구라 로직이 없음. 기존 단위 테스트 254개 모두 통과 유지

## 배운 점
- commander의 `addHelpText('after', ...)`는 도움말 끝에 자유 텍스트를 붙이는 자리. 명령어별 도움말이 아니라 프로그램 전체 도움말이라 환경 변수 안내처럼 한 번 보여주면 충분한 정보에 적합. 명령어별 도움말(`beoreum prospect --help`)에는 따로 안 붙음
- README의 환경 변수 표는 ADR 0024의 결정 표를 사용자 시점으로 한 번 더 풀어쓴 자리. ADR이 결정 자리라면 README는 사용자 자리. 같은 정보를 두 결로 적는 건 중복이 아니라 독자가 다르기 때문
